## Post-Task Procedure
1. 에러 처리 누락 여부를 점검한다.
2. 보안 위험(인증/권한/입력 검증)을 점검한다.
3. 타입 에러 가능성을 점검한다.
4. 결제/인증 수정 시 아래 상세 체크리스트를 점검한다.

### 결제 관련 수정 시 추가 체크
- [ ] confirm 전에 DB 주문 금액과 callback amount를 비교하는가?
- [ ] 주문 소유권 검증: orderId가 현재 사용자의 것인지 확인하는가?
- [ ] 멱등성이 DB 유니크 제약(UNIQUE)으로 강제되는가?
- [ ] 승인 API 호출이 서버에서만 일어나는가?
- [ ] 웹훅 원문(raw_headers + raw_body)을 저장하는가?
- [ ] 웹훅 서명 검증 또는 교차검증이 있는가?
- [ ] 상태 머신에 따른 상태 전이만 허용하는가?
- [ ] entitlement이 결제 상태와 분리되어 있는가?
- [ ] CSRF 방어가 confirm/환불 엔드포인트에 적용되었는가?
- [ ] 서버리스 타임아웃(10초)을 초과할 수 있는 처리가 없는가?

### 인증/RLS 관련 수정 시 추가 체크
- [ ] 모든 테이블에 RLS가 활성화되었는가?
- [ ] 4가지 operation(SELECT/INSERT/UPDATE/DELETE) 각각에 정책이 있는가?
- [ ] UPDATE 정책에 WITH CHECK 절이 포함되었는가?
- [ ] DELETE 정책이 존재하는가? (누락 시 운영 장애)
- [ ] auth.uid() IS NOT NULL을 모든 정책에 포함했는가?
- [ ] RLS 조건 컬럼에 인덱스가 있는가?
- [ ] 클라이언트 코드에서 service_role 키를 import하는 경로가 없는가?
- [ ] Security Definer 함수가 RLS를 우회하지 않는가?
5. 보고서 형식으로 기록한다: 발견 / 수정 / 판단 근거
